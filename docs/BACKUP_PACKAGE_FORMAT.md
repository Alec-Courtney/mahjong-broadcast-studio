# 赛事备份包格式 v1

0.1.3-preview 起，完整赛事和赛事设置的备份使用 `.mjbackup`，将数据与素材分开保存，解决旧版单个 JSON 备份超过 50 MB 时无法导入、导出的问题。包内采用 ZIP64，素材保存为独立二进制文件。

```
赛事名称.mjbackup
├── manifest.json
├── event.json
├── live.json
├── matches/000001.json
└── assets/imported/{images,logos,backgrounds,music}/内容哈希.扩展名
```

- `manifest.json`：`format=MahjongOverlayStudioBackup`、`format_version=1`、应用版本、创建时间、包类型、半庄文件顺序、全部成员的 SHA-256 与未压缩大小。
- 完整赛事包 `kind=event`：`event.json` 保存原会话版本（5/6）、赛事元数据、设置和最后和牌信息；`live.json` 保存实时 state，`broadcast.matches` 单独拆到有序半庄文件中。导入后重建与原模型一致的 state。
- 设置包 `kind=settings`：`event.json` 保存原赛事设置文档；无 `live.json` 和半庄文件。
- 用户实际引用的照片、队徽、Logo、标题卡、背景和音乐进入素材目录，历史半庄引用的旧素材一并保留。按现有内容哈希去重，同一路径只写入一次。
- 程序内置片尾和立直音效由安装包维护，不重复塞入每场赛事。全局偏好文件属于单独的设置交换，不是完整赛事备份。

文本数据合计最多 256 MiB，图片单文件最多 8 MiB，音乐单文件最多 512 MiB，素材合计最多 8 GiB。移除了旧 JSON 的素材合计 32 MiB、完整文件 50 MB 限制。导出按块读取音乐；导入先完整校验清单和内容摘要，再逐个读取素材，避免把全部音乐同时放进内存。

导出同一个文件名时，先写完整临时包，成功后原子替换目标，不创建带时间或编号的新副本。写入失败保留上一个包。导入拒绝重复成员、额外路径、缺失成员、错误校验值、不受支持的格式版本和超限内容。

## 本地保存与监听兼容

本地 `data/events/<赛事编号>/session.json`、`data/standalone/session.json`、`library.json` 及会话版本 6 保持不变。保存时的原子替换、修订冲突检查和稳定选手 ID 继续保留。现有只读点数监听助手仍读取相同文件、相同字段，不需要更换监听端或线上服务器。

导入素材后复制到 `assets/imported/` 的现有托管逻辑不变。相同内容重复导入复用同一份文件；修改点数、布局或音量不会再次复制原始素材。不同内容的素材使用不同哈希，历史成绩仍引用旧素材时不会被覆盖。

没有增加定时或每次操作生成的赛事备份包。`.mjbackup` 只在导出或转换时生成。音乐在启动或更换所选音乐后，后台预热既有解码缓存，不自动播放、不阻塞直播录入；普通成绩修改复用已有缓存。

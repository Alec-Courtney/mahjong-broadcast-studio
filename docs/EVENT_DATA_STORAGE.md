# 赛事数据与素材保存逻辑

每场数据保存到 `data/events/<赛事编号>/session.json`，`data/library.json` 保存当前赛事选择。导入素材复制到项目根的 `assets/imported/`，赛事共享相同内容的副本。原 `data/session.json` 首次迁移时保留，旧赛事内 `media/` 引用继续兼容。完整 JSON 携带赛事规则、进度、榜单配置及使用中的素材。 [赛事管理说明](EVENT_WORKSPACE_GUIDE.md)

每个选手使用固定的 `id`；姓名、队伍、照片及历史基数都挂在该 ID 下。更换座位或修改姓名不创建新选手，统计按 ID 汇总。

| 数据 | 保存位置与关联 |
| --- | --- |
| 选手名册 | `state.broadcast.roster`：ID、姓名、队伍、颜色、照片、基准积分和历史统计 |
| 团队赛队伍 | `state.broadcast.teams` 保存队伍名称和队徽。选手通过固定队伍编号关联。旧赛事可从现有名册和成绩恢复队伍 |
| 本场四席 | `state.players`：通过同一 ID 关联名册，另存当前点数、立直、听牌、副露 |
| 逐局记录 | `state.broadcast.hands`：每局点数、收支、统计以及当时的选手资料和照片 |
| 半庄归档 | `state.broadcast.matches`：逐局记录、最终积分及当时的四名选手资料快照 |
| 照片副本 | 项目根 `assets/imported/images/`；裁切前原图另存 `images/originals/` |
| 队徽与赛事 Logo | `assets/imported/logos/`，按内容去重并保持透明与比例 |
| 开场标题卡与赛后背景 | `assets/imported/backgrounds/`，使用项目相对引用 |
| 音乐 | `assets/imported/music/`，使用项目相对引用 |
| 导入数据原档 | 新导入的赛事原档保存在该赛事目录下的 `imports/`。旧版本与独立导播的导入原档保存在 `assets/imported/documents/` |
| 应用偏好 | `data/application-preferences.json`，主题、操作界面字体、字号和语言跨赛事共用 |
| 独立导播工作区 | `data/standalone/session.json`，不依赖赛事库；与赛事模式共用应用偏好 |
| 导出赛事 JSON | 包含名册、逐局与半庄记录、显示设置及使用中的内嵌素材，按校验值去重 |

会话保存使用短文件锁和修订校验。遇到「工作区已在其他窗口更新」时，通过主导播台「工作区 → 重新载入当前工作区」读取最新数据后继续录入。赛事索引和共享偏好在事务锁内读取、合并和写入。 [架构与数据边界](ARCHITECTURE_UX.md)

搬迁整个项目时一起复制 `data/` 和 `assets/imported/`。单独迁移赛事时，在「赛事管理 → 备份与说明」选择「导出完整赛事 JSON（含照片）」，到新设备导入为另一个独立赛事。只迁移播出配置和规则时，可使用「赛事设置 → 规则与设置文件」中的赛事设置文件。

导入先检查赛事结构、字体设置及素材校验值，再将素材托管到项目库。旧版无内嵌素材的 JSON 先按原文件夹解析相对引用；缺失素材会明确报错。新库文件按内容去重，旧照片、队徽及历史快照保持关联。完整 JSON 的素材合计上限为 32 MiB、文件上限为 50 MB；本地音乐可独立托管，不受 JSON 总量限制影响播放。

旧记录保留当时的姓名、队伍与照片。之后修改名册中的姓名或照片，不会回写已存在的资料快照；改判、重新确认积分仍更新原局和原半庄，不重复累计。

## 本地测试

赛事库内置「【演示】M.League 团队积分赛」，使用官网公开名册中的 10 支队伍、40 名选手和肖像。50 个已归档的模拟半庄包含逐局记录和技术统计，当前半庄可继续操作。也可将团队赛、个人赛或淘汰赛的 JSON 导入为独立赛事。[演示 JSON 与导入步骤](../demo-suite/README.md#下载后导入)

演示赛事拥有独立目录，安装后按普通赛事保存。旧版曾载入演示且仍保留恢复备份的工作区，可在「数据与导出」恢复测试前数据。

## 外观与布局

- 「系统设置」调整导播台与设置窗口的字体和字号。「赛事设置 → 画面与设备」调整播出字体及字号比例。
- 「画面与设备 → 布局与快捷键 → 四家布局」可设置四家的整体坐标、单家宽度和间距。
- 开启“四家联动”后，拖动任意选手同时移动四家；Ctrl＋滚轮统一缩放。关闭联动后恢复单家调整。
